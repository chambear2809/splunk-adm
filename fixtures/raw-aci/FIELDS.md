## cilium:hubble:flow

Line format: Hubble static exporter writes one `ExportEvent` per line, `{"flow":{…},"node_name":"<cluster>/<node>","time":"…"}` (`api/v1/observer/observer.proto:283-302`), marshalled with protojson `UseProtoNames: true` (`api/v1/flow/flow.pb.json.go:14-16`), so field names are proto names and enums are strings. Flow fields from `api/v1/flow/flow.proto`: `time uuid verdict IP{source source_xlated destination ipVersion} l4.TCP{source_port destination_port flags} source/destination{ID identity cluster_name namespace labels pod_name workloads} Type node_name l7{type http{method url protocol headers}} event_type traffic_direction trace_observation_point trace_reason is_reply trace_context.parent.trace_id Summary`.

- SNAT forwarding traces (c3a, c6): `IP.source` = original client, `IP.source_xlated` = node IP, ports and destination from the post-translation header (`pkg/hubble/parser/threefour/parser.go:251-264`).
- Reserved identities: world 2, remote-node 6, ingress 8 (Cilium reserved identity numbering).
- Envelope: Helm `logsCollection.extraFileLogs` filelog receiver (`values.yaml:780-791`, `templates/config/_otel-agent.tpl:745-753`, pipeline `logs/host` `:1215`), `source` = `com.splunk.source` (the file path `/var/run/cilium/hubble/events.log`, Helm `hubble.export.static.filePath` default), `sourcetype` set by `com.splunk.sourcetype`, `host` = node, fields `k8s.node.name`/`k8s.cluster.name` (agent `resource` processor `:859-868`) and `log.file.path` (`include_file_path`), `time` = observed (flow time + 1 s). Index `cilium` is a deployment choice.

## cisco:isovalent and otel:traces

Same shapes and citations as the NX-OS fixtures. Isovalent records cover pod-initiated connects only (frontend → checkout ×2, checkout → orders-db, payment → external, which shows the pod IP while the fabric sees node-a after masquerade). Spans name their pod explicitly. Server spans use OTel HTTP semantic conventions: `client.address` (original client, from X-Forwarded-For behind Envoy) and `network.peer.address` (immediate peer: Envoy's ingress IP, the SNAT node, or the VM).

## Not grounded; omitted or flagged

- **fabricNode** (switch model) is collected only by the health writer (`bin/cisco_nexus_aci.py:756-830`), which merges `healthInst` attributes not inspected here; omitted. topSystem supplies name, role, serial and addresses.
- **vzFilter** objects: MIM attribute list not inspected; omitted. The filter name is carried by `vzRsSubjFiltAtt.tnVzFilterName` and the vzEntry DN.
- **ACI NetFlow ifIndex**: APIC has no ifIndex→port mapping; `input_snmpidx` uses the NX-OS Ethernet encoding (0x1A000000 + (port−1)·0x1000), unverified for ACI exports.
- **acllog value formats**: `srcIntf` (`eth1/5`), `srcEpgName`/`dstEpgName` (EPG/ExtEPG DN) and `vrfEncap` (`vxlan-<vnid>`) formats are unverified; attribute names are from the MIM.
- **fabricLink DN `lnkcnt-{n}`**: uses the spine node ID; one object per physical link (whether APIC also stores the reverse direction is unverified).
- **Host LLDP values** (`sysDesc`, `capability`, `portDesc` = NIC name, `monPolDn=uni/infra/moninfra-default` on access ports) follow LLDP semantics but are not from a real host adjacency sample.
- **Hubble**: L7 flow `traffic_direction` and the IPs Cilium reports for Envoy L7 access-log flows, `event_type` numbers (4 trace / 129 access log, sub_type equal to the observation point), whether SNAT `TO_NETWORK` traces survive default monitor aggregation, and Isovalent Enterprise's export format all need real samples.
- **ND flows on ACI**: whether `nodeNames` includes spines, and the `srcEpg` value format, need samples.
- **Gateway/HTTPRoute status conditions** and HTTPRoute `status.parents` are omitted.

## Scenario decisions and gaps

- **node-c address**: 10.10.22.13 in the floating-SVI subnet 10.10.22.0/24, instead of 10.10.20.13. A floating-SVI L3Out subnet cannot overlap BD `bd-nodes` (10.10.20.0/24) in the same VRF.
- **Classification**: traffic entering an EPG port is classified by that EPG, not by source prefix. Pod-sourced traffic from node-a/node-b is therefore EPG `k8s/nodes`; only traffic entering via the L3Out (node-c) or destined to non-endpoint addresses classifies by ExtEPG prefix. Contracts are defined to match (for example `k8s-to-db` consumers are EPG `k8s/nodes` and ExtEPG `k8s-pods`). Expected classification per conversation is in `scenario.json` (`aci_class`).
- **Blocked attempt (c8)**: logged through an explicit deny-with-log subject (`win-deny-db`); logging of implicit (no-contract) drops is not established for ACI, so it is not relied on.
- **Masquerade**: Cilium `bpf.masquerade: true` with `ipv4NativeRoutingCIDR: 10.0.0.0/8` (Cisco's Cilium-on-ACI designs enable masquerade). Pod → VM/DB keeps pod IPs; pod → internet (c5b) appears on the fabric as node-a.
- **DSR dispatch**: per-service DSR requires `bpf.lbModeAnnotation=true` and `loadBalancer.dsrDispatch=ipip`, and IPIP requires port = targetPort (cart-api 8080/8080).
- **ingress-nginx removed** per scope change; c2 is a plain LoadBalancer Service with `externalTrafficPolicy: Local`, and c1d exercises Cilium Ingress (dedicated mode) alongside the Gateway (c1).
- **Synthetic values**: TEP, OOB and controller serial, UIDs (uuid5), MACs, `resourceVersion`, identity numbers, endpoint IDs, pcTags, VRF VNID, healthCheckNodePort, ESXi/Linux LLDP descriptions, VM OS strings.
