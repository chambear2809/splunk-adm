## Platform support check

- The [Cilium 1.20.5 requirements](https://docs.cilium.io/en/stable/network/kubernetes/requirements/) define listed Kubernetes versions as the e2e-tested compatibility set and say newer versions depend on Kubernetes backward compatibility. The inventoried Kubernetes 1.37 combination is therefore not covered by that stated tested range; this is an unqualified combination, not evidence of failure.
- Cisco's [Nexus 9000 NX-OS 10.6 NetFlow guide](https://www.cisco.com/c/en/us/td/docs/switches/datacenter/nexus9000/sw/106x/config-guides/sys-mgmt/cisco-nexus-9000-series-nx-os-system-management-configuration-guide-release-106x/m-configuring-netflow-104x.html) describes applying monitors to interfaces and exporting at timeout/cache flush. The recorded cache reads establish only the observed tuples/ports in their windows; they do not qualify continuous Stream ingestion.
- Splunk's [Enterprise 10.6 release notes](https://help.splunk.com/en/splunk-enterprise/release-notes-and-updates/release-notes/10.6/whats-new/welcome-to-splunk-enterprise-10.6) identify 10.6.1 as released October 16, 2026. The lab's exact 10.6.1.1 build and installed add-on combinations remain bound to the recorded target; no broader compatibility or source qualification is inferred.
- The configured Kubernetes connector defaults to a separate EKS demo context, while the validation target in the current records is a K3s node. It was not used to run or mutate the validation cluster. The pending Kubernetes scenarios require the existing target-scoped K3s access path to be selected explicitly.
