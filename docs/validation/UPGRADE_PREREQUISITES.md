## Compatibility and package gates

The [Splunk product compatibility matrix](https://help.splunk.com/en/splunk-enterprise/release-notes-and-updates/compatibility-matrix/splunk-products-version-compatibility/splunk-products-version-compatibility-matrix) lists ES 8.1.0 with Enterprise 9.4.x, but does not list ES 8.1.0 with 10.2.x. ES 8.5.1 appears in both rows, making it a candidate bridge for investigation, not proof of a complete supported upgrade sequence. Enterprise 10.2.x lists ES 8.8; the 9.4.x row does not.

The matrix lists ES 8.4.1, 8.5.1, 8.6.1 and 8.7.x for Enterprise 10.6.0 with asterisks. Its 10.6.1.0 row warns that ES 8.7 and lower are incompatible with cohosted KV Store 1.0. The extraction did not present a separate explanation next to the 10.6.0 asterisks; obtain Splunk's clarification for the exact patch and migration behavior. This matters because Atlas's qualified write gate requires ready cohosted PDL. Enterprise 10.6.1.1's matrix row lists ES 8.8.x and earlier listed versions, and states that ES 8.4.x and later are compatible with that platform version. Verify the exact ES, KV Store and platform combination with Splunk rather than extrapolating the 10.6.1.0 warning or assuming that a platform compatibility row qualifies every KV migration path.

Splunk's [ES 8.8 release notes](https://help.splunk.com/en/splunk-enterprise-security-8/release-notes-and-resources/8.8/splunk-enterprise-security-release-notes/release-notes-for-splunk-enterprise-security) state 8.8.0 reached general availability on November 4, 2026. Its [upgrade guide](https://help.splunk.com/en/splunk-enterprise-security-8/install/8.8/upgrading/upgrade-splunk-enterprise-security) covers on-premises upgrades from ES 7.x or later, requires a full search-head and KV backup, and requires a licensed customer to obtain the installer. The supplied package's availability is established separately below. Neither an archive nor a platform license establishes every contractual entitlement or successful installed compatibility.

Splunk's [download listing](https://www.splunk.com/en_us/download/splunk-enterprise.html?d=free) identifies Enterprise 10.6.1.1 build `b2ae2962645c`; the matching official package has now been downloaded and publisher-checksum verified locally and on the target. The vulnerable 10.6.0.5 build is not the selected upgrade target. Splunk's [SVD-2026-1104](https://advisory.splunk.com/advisories/SVD-2026-1104) identifies 10.6.0.5 as affected by listed third-party issues and 10.6.1 as a fixed release, with component-specific differences. Review the full advisory and applicable fixes for the selected exact build. Atlas currently pins its settings, recovery and cases write gates to 10.6.0.5; 10.6.1.1 requires separate implementation and installed-runtime qualification before Atlas writes are enabled. Platform compatibility alone does not satisfy that gate.

## Documented upgrade route

Splunk's [platform upgrade matrix](https://help.splunk.com/en/splunk-enterprise/administer/install-and-upgrade/10.6/upgrade-or-migrate-splunk-enterprise/how-to-upgrade-splunk-enterprise) requires an intermediate release from 9.4.x; its [KV Store guidance](https://help.splunk.com/en/data-management/splunk-enterprise-admin-manual/10.6/administer-the-app-key-value-store/upgrade-the-kv-store-server-version) additionally requires Enterprise 10.2 or later and KV Store server 7.0 or later before 10.6. The current [ES 8.8 planning guide](https://help.splunk.com/en/splunk-enterprise-security-8/install/8.8/upgrading/planning-an-upgrade-of-splunk-enterprise-security) recommends upgrading Enterprise first, then ES in the same maintenance window, and says simultaneous upgrades do not require stepped ES upgrades. The 8.8 upgrade guide covers ES 7.x and later, while the compatibility matrix lists ES 8.8 with Enterprise 10.2 and 10.6.1.1. Together these support planning Enterprise 9.4.3 → compatible 10.2.x → ES 8.8.0, followed by Enterprise 10.6.1.1, without assuming an ES 8.5.1 bridge is mandatory. Follow the documented platform-first procedure in one maintenance window and immediately complete ES upgrade and setup on 10.2; this is a transition, not a claim that ES 8.1 is supported on 10.2. The documentation does not say that disabling only the main ES app disables every dependent component, so do not assume it does. Check the cohosted KV migration and application health before resuming service. The vendored ES automation's 8.5.1 package pin and older release metadata are separate from this newer vendor documentation and do not validate ES 8.8 or the proposed sequence.
