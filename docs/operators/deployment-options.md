# Deployment options and missing sources

Use this guide to choose the sources and jobs for your deployment before following the [Splunk setup sequence](splunk-setup-guide.md). The original ACI pilot and the Catalyst → ACI / Meraki wireless → NX-OS demos are examples, not a requirement to install every product.

## Release and qualification boundary

The merged release ships V1 public readers (`adm_data_contract_version=1`). Catalyst/Meraki live enrichment is optional V2 functionality: its writers ship disabled and activation requires the [staged migration procedure](../CISCO_CONTRACT_MIGRATION.md) and [target-specific qualification](../CISCO_NETWORKING_QUALIFICATION.md). Selecting a captured demo does not activate V2, configure collectors, or establish live readiness. The V2 helper accepts only its qualified standalone Enterprise deployment shape; do not apply it to Cloud, SHC, or distributed/indexer-cluster deployments.

Current engineering evidence is recorded in [final qualification](../ATLAS_FINAL_QUALIFICATION.md): the complete standalone installed suite, separate V2 migration/browser acceptance, and a three-member SHC with a separate deployer and indexing/search peer passed on Enterprise 10.6.0.5 with synthetic data. The SHC used one host and is bounded evidence for V1/staged-V2 application behavior and shared settings, not a production topology or V2 cutover qualification. See [the exact SHC procedure and limits](../SHC_FINAL_QUALIFICATION.md). The standalone migration helper continues to refuse SHC and distributed targets.

Synthetic checks do not qualify actual controller API collection, exporter decoding, production capacity, or a customer deployment. Cloud runtime and formal vetting remain open gates. Earlier [Cisco qualification records](../CISCO_NETWORKING_QUALIFICATION.md) retain their historical package boundaries; use the final qualification record for current results.

## Choose evidence by the question you need to answer

| Source                                                                                           | What it contributes                                                           | When absent                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stream NetFlow/IPFIX, Nexus Dashboard flows, FTD, Isovalent process connections, or Hubble flows | Observed conversations, with source-specific counters and provenance          | Inventory alone cannot prove a conversation; missing observations do not prove no traffic. These feeds are alternatives with different coverage, not interchangeable measurements. |
| ACI endpoint, fabric and policy objects                                                          | Endpoint identity, EPG/BD context, candidate fabric paths and policy intent   | No ACI-specific context; other available traffic and workload evidence can still contribute.                                                                                       |
| NX-OS / network inventory                                                                        | Device, interface and adjacency context                                       | Traffic may remain visible without a resolved device or physical attachment.                                                                                                       |
| Kubernetes object history                                                                        | Pod/workload identity, Service frontends, backends and routes                 | IP identities and backend handoffs may remain unresolved. The application-oriented selectors still need a discoverable application or explicit Find target.                        |
| OpenTelemetry traces                                                                             | Service calls and service-to-workload bindings                                | Network-derived conversations remain useful without call-level trace detail.                                                                                                       |
| Catalyst Center client observations (V2)                                                         | Source-qualified client identity and receipt-eligible attachment observations | No Catalyst client enrichment. Available flow records may still identify an IP endpoint. A snapshot by itself is not a traffic path.                                               |
| Meraki association events (V2)                                                                   | Time- and source-scoped wireless attachment evidence                          | No association-based AP/SSID attribution. NetFlow alone does not establish that a client was wireless.                                                                             |
| Hubble handoff evidence plus Kubernetes history                                                  | Evidence for a selected client's backend and receiving node                   | A Service frontend may remain visible while its backend boundary is unresolved; aggregate backend traffic cannot substitute for that client's evidence.                            |

Absent sources, permissions, ambiguous identities and incomplete reads must remain explicit gaps. Never fill a live-data gap with captured demo rows. Do not create unused vendor inputs or grant broad index access just to silence a warning.

## Choose V1 jobs

All saved searches ship disabled. Enable only the jobs needed for the evidence and features you selected, after their prerequisites are configured. Setup derives enable prerequisites from saved source expectations and the active contract, using `config/deployment-health.json`. Shared pipeline searches can still reference multiple source indexes; source selection is not a general switch that removes every unselected source from every search. Review search messages and effective permissions on your target.

| Saved search                  | Enable for                                                                                                                                                                                      |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ADM - Identity builder**    | Kubernetes pod/node history and/or ACI/Nexus Dashboard endpoint identity.                                                                                                                       |
| **ADM - Service binding**     | Trace-derived service/workload bindings; pod resolution depends on available identity history.                                                                                                  |
| **ADM - Service backends**    | Kubernetes Service, EndpointSlice, Ingress/Gateway and backend history.                                                                                                                         |
| **ADM - Interface inventory** | Available device/interface metadata from the supported network sources.                                                                                                                         |
| **ADM - ACI policy**          | Collected ACI policy objects; absence of a matching permit does not establish a denial unless policy completeness has been verified.                                                            |
| **ADM - Conversation rollup** | Supported V1 traffic feeds; writes `adm_summary` by default.                                                                                                                                    |
| **ADM - Application catalog** | Scheduled application discovery from the configured graph inputs; supplements explicit Find. Runs hourly at minute 15, so do not assume the catalog is populated 15 minutes after installation. |

For V2, keep **ADM - Network client history builder**, **ADM - Conversation rollup v2**, **ADM - Traffic observation rollup v2**, and **ADM - Application catalog v2** disabled until the migration procedure authorizes their transitions. Do not manually edit public selectors to bypass staging. Keep every prune schedule disabled; use the [paused-writer maintenance procedure](../RECOVERY.md#pruning-and-maintenance) for pruning. Recovery actions and their alerts require their own explicit setup in that same recovery guide.

## Check a partial deployment

Record the selected sources, expected collection cadence, indexes, routing scopes, cluster identities, required jobs and known gaps with the deployment. Create/configure only the source inputs you selected; create the summary indexes required by the active contract. Validate raw receipt and schema before relying on derived output. Unmapped observers remain isolated in authority-qualified `unmapped:<hash>` scopes; configure explicit shared routing scopes before expecting cross-source correlation.

In **Setup**, administrators select each source as active, staged or not selected, with cadence and receipt-freshness expectations. Settings persist through the authenticated deployment-settings endpoint. **Writes ship disabled**: qualify the exact deployment and distribute the persistence gate described in [deployment health](../DEPLOYMENT_HEALTH.md#supported-write-contract-and-deployment-gate) before saving. The runtime gate is pinned to Enterprise 10.6.0.5. One standalone search-head KV namespace can use `single_namespace`; SHC requires its separately coordinated `qualified_shc` procedure and all-member/concurrency evidence. Independent search heads behind a load balancer do not share a namespace. Cloud and unqualified targets remain read-only; do not bypass that refusal by writing KV rows directly.

No saved expectations is a supported upgrade state: existing maps/searches still work, while deployment health stays unknown and Setup cannot enable jobs without the required saved intent. Saving expectations does not configure collectors, edit routing profiles, activate V2 or enable searches. Sources requiring V2 remain staged while V1 is active. **Data health** dispatches source/quality probes only for configured applicable sources; unselected sources add no unrelated index errors. Selected but unreadable or incomplete evidence remains unknown. Quiet feeds and stale receipts need investigation rather than an assumed collection outage.

The [read-only readiness analyzer](../PILOT_READINESS.md) uses the same source/job registry. `--lab` with no explicit source reads saved deployment expectations; explicit `--source` arguments scope an investigation without saving intent. Available selections include `netflow`, `dcn`, `aci`, `nd`, `nxos`, `ftd`, `isovalent`, `k8s`, `traces`, `hubble`, `catalyst`, `meraki` and `sdwan`, plus the legacy `summary` inspection option. Without `--lab`, at least one `--source` is required and the CLI analyzes an empty snapshot; it does not connect to production Splunk or vendor APIs. Actual collector permissions and continuity need separate evidence.

Validate the live map against the selected evidence, including negative cases: no Meraki AP/SSID without association evidence, no ACI policy without policy objects, and no resolved backend without compatible handoff evidence. Inventory, observation points, inferred candidates and ordered packet routes are distinct claims.
