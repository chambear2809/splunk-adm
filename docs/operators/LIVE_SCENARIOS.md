## Atlas gaps found

1. **ACL-log re-polls are counted.** `adm_path_flow_normalize` is used by `adm_path_trace` and `adm_device_flows`, and it lacks the `adm_acl_age` first-poll filter that `adm_flows_acllog` has. Old drops therefore show up in every window. For example, at 16:04 a 5-minute trace window reported 30 drops last logged at 15:36, and the 47003 deny had been removed at 15:37.
2. **No Blocked badge in standalone traces.** The graph has no edges, so `trace.conversations` is always empty.
3. The vPC hop is not narrowed when only one leaf exporter observed the flow.
4. Same-host traces get an inferred FI hop.
5. L3Out addresses get no attachment from `l3extRsPathL3OutAtt`.
6. Hubble is not used in pair traces, and DROPPED verdicts are discarded.
7. **Identity intervals.** The running pod `teastore-webui-v1-689b599b6c-szx6x` (10.245.0.159) has no `adm_ip_identity` row. Pods with DELETED events (for example `teastore-auth-85777d858b-lgx97`) keep open intervals.
8. The trace summary "ports" mixes reverse-direction client ports (47110–47117) into the service ports.

## Fixes

| # | Root cause | Fix |
|---|---|---|
| 1 | The pair and device searches normalized ACL-log records without the first-poll rule. | `adm_path_acl_first_poll` (in `adm_path_flow_normalize`) keeps a record only from a poll at most `adm_poll_interval` + 60 s after its `timeStamp`, keeps it once per APIC and record DN, and windows it by `timeStamp`. `adm_device_flows` applies its record cap after normalization. Against the live data, the 96.50 → 10.101.255.41 pair has no drops in any window (every buffered record predates its first collected poll), and the scenario C deny shows 24 drops at node-102 and 6 at node-101 between 15:29:55 and 15:36:20. |
| 2 | `blockedHops` read only graph conversations, and a deep-linked trace has none. | `pathTraceDrops` reads the drop rows of `adm_path_trace` (`drop_services`, `drop_reasons`). The trace marks the enforcing leaf, or the vPC/ECMP hop that contains it, with "Blocked tcp/47003 (ACI contract)", and services with records but no drops show as not blocked. |
| 3 | vPC members were placed as one stage. | When exactly one member observed the pair in the window, the hop becomes that leaf and the other is listed as "not seen". "One of 2 leaves" stays when both members observed the pair, or neither did. |
| 4 | With a shared host, VDS and VLAN, the client attachment still carried its uplink stages (FI pair). | The path is VM → VDS → VM unless a leaf observed the pair, in which case it is drawn through the fabric with that leaf observed. |
| 5 | No macro read `l3extRsPathL3OutAtt`. | The L3Out patch (`adm_l3out_path_evidence`) was applied first. Live, 10.110.96.3 → 10.110.254.6 ends at leaf102 eth1/24 (L3Out CV-L3Out-01). The leaf hop is leaf102, observed, with leaf101 not seen. |
| 6 | `adm_path_trace` did not read Hubble, and the graph's Hubble search keeps only forwarded flows. | `adm_path_trace` and `adm_device_flows` read every Hubble verdict (`adm_path_hubble_fields`). DROPPED and ERROR count as drops and AUDIT counts as an audit, each with `drop_reason_desc`. The pair rows include the cluster, namespace and node identity of pod endpoints and their node rows (`adm_path_pod_nodes`). The trace places a pod behind its node, attaches the node through its VM vNIC, and shows "Blocked (Kubernetes policy)" at the Cilium node. `adm_flows_hubble` and the `adm_graph(4)` closure are unchanged. |
| 7 | Automatic JSON extraction reads only the first `limits.conf [kv] maxchars` (10240) characters. The teastore pod objects are 11–14 KB, and the OTel k8sobjects watch event puts `status` (podIP) and `type` (DELETED) at the end, so the IP and the deletion were never seen. | `adm_identity_k8s_raw` reads the pod and Node fields with `spath` from `_raw`. `adm_identity_pod_absence` closes an open pod interval at `observation_started_at` of the newest complete Atlas point snapshot (`adm:k8s_pod_node_snapshot:v1`) that omits the pod. A snapshot counts only with one manifest that has `complete=true` and `namespace_scope=all`, and an `expected_count` equal to its object records and to its distinct fingerprints and UIDs. |
| 8 | The summary listed `dest_ports` from both directions. | `adm_path_service_port` names the listener side of each record: the address:port with more distinct peer ports, then a system port, then a non-ephemeral port, then the lower port; a Hubble reply's source is always the listener. The summary shows services such as tcp/47001 and tcp/47003, and client ports appear only in the endpoint detail. |

Data-model limits:

- Intervals that were left open before the fix stay open until the builder reprocesses their DELETED event. Backfill `ADM - Identity builder` once with `index_earliest` covering the affected days (-7d).
- Absence closes only `entity_kind=pod` rows (not hostNetwork pods, Services or nodes). It needs a complete Atlas point snapshot indexed in the builder window. The live producer stopped at 2026-11-03 19:54, so on the lab only DELETED watch events close intervals today.
- Hubble flows between pods on different nodes are VXLAN-encapsulated (8473) on the fabric, so the hops between the nodes stay inferred. A Kubernetes policy drop is placed only at the node that reported it.
- The listener heuristic needs either several client ports or a non-ephemeral port. A single connection between two ephemeral ports takes the lower port.

Repeatable read-only checks are in `tests/live/test_live_scenarios.py`. Run them with `ADM_LIVE=1 ADM_LIVE_SEARCH=<csv search helper> python3 -m unittest tests/live/test_live_scenarios.py`. They need an Atlas build with these fixes, which the deployed 0.7.3 does not have. Lab regressions are in `tests/splunk/test_live_scenario_gaps.py`, unit tests in `tests/test_path_trace_macros.py` and `frontend/src/trace/liveScenarioGaps.test.tsx`, and browser tests in `tests/browser/trace-gaps.spec.ts`.
