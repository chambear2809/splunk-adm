## Implementation boundary

The endpoint workflow reads the administrator-configured active V1/V2 summary index without requiring a Kubernetes namespace or trace catalog. It retains scoped addresses, observation intervals, direction basis, provenance, sampling and separate nonauthoritative V2 observations. Root identity history is shown without collapsing an address into one owner. Peer navigation starts another bounded one-hop investigation.

Stream DNS and Hubble DNS L7 use separate on-demand normalization adapters. New searches compile literal selectors, use caller credentials, and read explicit app/shared scope and identity collections. DNS settings are unselected by default, optional readiness is separate, and no collector, policy, scheduled builder, summary counter, ownership collection or graph-snapshot format is changed. Loaded DNS data are retained only for the current selection; explicit JSON/CSV downloads are the portable evidence record.

The product enforces a 24-hour requested window, configured 60–86400 second association-age cap, eight selected client addresses, eight actual peer addresses for selected map edges, 256 retained traffic contexts, 100 peers, 500 relationships, 10000 source records plus sentinel, 64 displayed DNS observations, 64 answer values, 32 aliases, 1024 displayed name characters and a 1 MiB raw-record parse limit. Caps and incomplete execution remain distinct. Browser admission allows two optional jobs, one per adapter; creation/cancellation uncertainty keeps the native lease occupied. Status checks may confirm terminal/deleted jobs but do not rerun DNS. No browser limit establishes deployment-wide capacity.

Search requests opt into native `max_time=30`, `auto_cancel=30`, no auto-pause and a 35-second client deadline; existing callers retain their 120-second client default. Native completion, cancellation and quota behavior must be measured for every claimed target. An unacknowledged creation or unverifiable cleanup remains an explicit unavailable/pending condition rather than proof that a server slot is free.

The [scenario guide](DNS_EVIDENCE_SCENARIOS.md) distinguishes implemented generic evidence behavior from topology-specific examples that still require genuine feeds. In particular, native parallel address/TTL arrays and unordered address sets remain context only: qualification flags cannot create missing RR-owner/answer-section relationships.
