# Local synthetic benchmark results — 2026-10-13

Seven workload cases completed with exact expected counts and no search or graph warnings. Two deliberate boundary probes returned incomplete status: the 802-node graph raised the size warning, and 100 connections per summary row exceeded the shipped 50-connection list. The full command therefore exited 1 as expected; the boundary cases are not accepted capacity measurements.

This is an initial sizing baseline for the future pilot. It establishes correctness and timings for these synthetic batches, not production capacity or sustained flow records per second.

## Environment and evidence

- Local Splunk 10.6.0.5, x86 Linux container under emulation on an ARM64 Mac.
- Docker allocation: 12 CPUs and 7.65 GiB memory; no additional per-container CPU or memory limit.
- One first graph request, then three waves each at 1, 2 and 4 simultaneous requests: 22 graph requests per case, 198 total.
- Configuration matched the repository defaults at preflight. Runner, generator and search hashes still matched after the run. The checkout was uncommitted; source hashes, rather than the Git revision alone, identify the measured code.
- [Raw measurements](2026-10-13-local.json) retain workload and source hashes, exact expectations, each query runtime, warning text, indexing timings, and memory sample counts and peaks. [Methodology and rerun instructions](../BENCHMARKS.md) describe the checks and limitations.

## Networking-device checks

- **Exporter count:** `one-device` and `many-devices` hold 10,000 records and 100 backend pods constant, changing exporters from 1 to 100. Both passed. Their map timings were effectively the same in this run; this does not measure actual device transport or collector overhead.
- **Overlapping observations:** `shared-observers` ingested 30,000 records from 100 exporters, with three observers per pair. The summary preserved 9,000,000 raw bytes while the graph correctly showed 3,000,000 bytes after reconciliation, with 100 distinct connections.
- **Distinct connections:** `unique-connections` validated 5,000 connections across 100 backend pairs, with 50 connections per pair. Physical export records and unique connections are tested separately.
- **Identity history:** ten incarnations per backend IP produced 1,002 identity rows. Expected identity and binding counts, graph counts and traffic totals passed. Median graph time at four concurrent requests rose from 1.74 seconds without retained history to 3.15 seconds with it.

## Boundary probes

| Case | Observed outcome | Interpretation |
| --- | --- | --- |
| wide-graph | 100,000 records, 100 exporters, 4,002 identities, 802 nodes and 1,201 edges; expected counts and bytes matched. Graph warned above 500 nodes. | Incomplete by the harness quality gate; narrow the graph scope before treating this as a normal workload. |
| connection-cap | 100 distinct connections per summary row; graph counted 500 of the expected 1,000 total connections and warned that 10 rows listed only their first 50. | Connection counts and hand-offs are approximate above the shipped per-row cap. This is not silent truncation and must remain visible. |

The wide graph rolled up in 4.90 seconds. Its graph median was 7.93 seconds at concurrency 1 and 8.86 seconds at concurrency 4 (maximum 9.71 seconds). These timings describe a warned result, not an accepted capacity point.

## Memory and remaining validation

Across the seven completed cases, sampled whole-container peaks ranged from 5.51 to 5.59 GiB. All nine cases had memory samples with no sampling errors. The cgroup metric includes filesystem cache and supporting processes; it is not per-query memory, a cold-start measurement, or a recommended memory allocation.

The pilot still needs sustained ingestion, actual exporters and sampling configurations, mixed source formats, competing scheduled searches, intended Splunk hardware/topology, and browser rendering checks. Repeat at the pilot’s actual size when known. No live network or cloud environment was used.

Tooling validation: 18 unit tests passed, including 15 benchmark tests; Ruff lint and formatting checks passed. Independent review of the harness found no remaining actionable issues after corrections.
