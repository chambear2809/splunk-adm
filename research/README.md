# Research Artifacts

Downloaded add-ons are stored in `packages/`; extracted files for inspection are stored in `extracted/`. Both directories are ignored to keep vendor archives, compiled collectors, and copied libraries out of the project source. The retained [manifest](package-manifest.json) records version, source, checksum, extraction location, and access status.

Eight archives are available locally: Stream Wire Data 8.1.6, Stream Forwarders 8.1.3, Stream App 8.1.6, AppDynamics 3.2.1, OTel Collector 0.162.0 (Linux), Cisco Security Cloud 3.6.5 and 3.7.2, and Cisco DC Networking 1.2.2. Their findings are in [TA package analysis](../docs/TA_PACKAGE_ANALYSIS.md). Sources are the publisher's GitHub release, a public package mirror explicitly referenced by Splunk's `security_content` repository, and authenticated Splunkbase downloads. The three authenticated downloads match their publisher digests. No package was installed or executed.

[Cisco Enterprise Networking](https://splunkbase.splunk.com/app/7538) is relevant if the Smart Switches are supported Catalyst/IOS XE devices. The inspected Stream Forwarder is an older baseline; obtain and inspect the actual deployment version before configuring the pilot. Save additional archives in `research/packages/`; retain their original filenames and update the manifest after extraction.

For each package, inspect `default/inputs.conf`, `README/inputs.conf.spec`, `default/props.conf`, `default/transforms.conf`, lookups, and modular input code. Follow its data request and event-writing path to distinguish available fields from automatically collected fields. Record missing inventory/topology collection explicitly. Use representative events to validate field presence, cardinality, timestamps, routing domains, and collection completeness.
